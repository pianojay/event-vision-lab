# CPU timing reference results — November 22, 2026

This is a scalar **ideal log-signal** experiment, not a Godot GPU run, external simulator reproduction, real-camera characterization or whole-scene timing benchmark. Implementation base is `7e90917`; source SHA-256 values and Python/OS/processor strings are stored in [summary.json](evidence/2026-11-22/summary.json). CPU: Intel family 6/model 126 (the project laptop's i7-1065G7). Python 3.14.8, Windows 11 build 26300. No GPU was used; CPU frequency, power mode and background load were not controlled, so the recorded wall durations must not be generalized to throughput requirements.

## Method

Compare an independent continuous trajectory inversion with a persistent sample-driven ideal pixel. Hand-calculated ramp, asymmetric-threshold, reversal and sinusoid tests anchor the oracle. Six scalar fixtures, four nominal rates (120/240/480/960 Hz), 16 phases and four strategies give **1,536 cases**. Each fixture lasts 0.1 s with `C_on=C_off=0.2`:

- Triangular pulses of width 1/4/16 ms, peak log change 0.7. Flat before and after; width includes rise and fall, not a square-wave plateau. Each has three ON and three OFF events in the continuous oracle. Pulse starts at `0.025 + phase_index/(16*rate)` seconds.
- Sinusoidal log intensity of amplitude 0.7 at 5/30/90 Hz. Initial phase is `phase_index*2*pi/16`; initialize from that phase's starting value.

The fixtures are continuous in log intensity. They are not calibrated lamp waveforms. They intentionally isolate temporal sampling from rendering, sensor dynamics and visualization.

Strategies:

| Strategy | Information used | Limitation |
| --- | --- | --- |
| Uniform | Nominal fixed rate; exact run end included | Can hide pulses/reversals and shift crossing times |
| Known boundaries | Uniform times plus every piecewise knot or sine extremum | Privileged known trajectory; sine is still nonlinear between those points |
| Slope bound | Uniform densification so maximum global log slope times interval is at most `C/4` | Global bound is known analytically; not ESIM or a general event-count guarantee |
| Midpoint adaptive | Refine until midpoint deviation from endpoint interpolation is at most `C/4`, depth limit 12 | A hidden excursion can evade endpoints and midpoint; not a validated sampler |

`sample_count` counts accepted sensor-input observations. The midpoint strategy's separate schedule-evaluation counter includes rejected/probed midpoints; accepted sample count alone understates its cost. Wall milliseconds cover schedule selection and CPU sampled-event generation, excluding oracle, comparison, export and any engine/rendering work.

Events are matched in chronological order independently per pixel/polarity using a fixed **0.5 ms** tolerance. Earliest-compatible matching maximizes ordered match cardinality; it does not optimize timestamp residuals or infer true correspondence when many events are close. Missing and extra events are reported, alongside raw ON/total counts. A timestamp error above the gate becomes an unmatched reference and observed event. Thus all reported *matched* errors are censored by the gate: a low matched p95 alone is not success. Empty matched sets report null errors, not zero. Summary count error is also recorded independently of matching.

## Selected observations

| Fixture / strategy | Nominal rate | Fully missed pulse phases | Phases with no unmatched events inside gate |
| --- | ---: | ---: | ---: |
| 1 ms pulse / uniform | 120 Hz | 15/16 | 0/16 |
| 1 ms pulse / midpoint adaptive | 120 Hz | 14/16 | 2/16 |
| 1 ms pulse / known boundaries | 120 Hz + boundaries | 0/16 | 16/16 |
| 4 ms pulse / uniform | 120 Hz | 11/16 | 0/16 |
| 16 ms pulse / uniform | 120 Hz | 0/16 | 1/16 |
| 30 Hz sine / uniform | 120 Hz | Not a pulse | 0/16 |
| 30 Hz sine / uniform | 240 Hz | Not a pulse | 6/16 |
| 30 Hz sine / uniform | 480 Hz | Not a pulse | 16/16 |
| 30 Hz sine / uniform | 960 Hz | Not a pulse | 16/16 |

In the narrow-pulse example, [uniform sampling exports no events](evidence/2026-11-22/pulse-uniform.csv), while the [continuous oracle](evidence/2026-11-22/pulse-reference.csv) and [known-boundary sampler](evidence/2026-11-22/pulse-known-boundaries.csv) both export all six. This proves the sampled-signal ambiguity in this fixture, not that the current game's scene has that exact event loss rate.

Sampling every piecewise-linear knot reproduces the continuous piecewise-linear events to floating-point precision. It is an oracle-informed control for a renderer that knows its lighting changes, not a black-box flash detector. For a sine, adding extrema preserves its amplitude range but does not make crossing times exact; additional samples are needed inside curved segments.

The slope-bound strategy costs 2,801 input samples per 0.1 s for the 1 ms pulse, compared with 13 nominal uniform samples at 120 Hz and 15–16 samples with known boundaries. Its small allowed brightness increment does not guarantee all threshold-touch events: the exact sine extrema can coincide with thresholds and an arbitrarily close sample still miss the touch. Tests explicitly define equality as triggering. This sensitivity and phase dependence prevent declaring a general supported envelope from these fixtures.

## Clock arithmetic

Rounding absolute seconds to IEEE binary32 gives the following adjacent-value spacing and difference between rounded `t+1/120` and rounded `t`:

| Elapsed time | FP32 spacing | Represented next 120 Hz interval |
| ---: | ---: | ---: |
| 3,600 s | 0.244140625 ms | 8.30078125 ms |
| 86,400 s | 7.8125 ms | 7.8125 ms |
| 262,144 s | 31.25 ms | 0 ms |

These are numerical arithmetic results, not measured GPU events. They motivate relative times/bounded epochs and a duration-specific precision budget. CSV integer nanoseconds avoid discarding precision by adding a large epoch in float; binary64 relative computation and nanosecond rounding still have finite precision.

## Validation and limits

**16 tests passed**, covering hand-calculated crossing times, persistent residuals, polarity asymmetry, static/reset silence, interval ownership, same-sample batching, hidden pulses, sine convergence/touches, gated matching, CSV round-trip/ties/large epoch/overflow, malformed input and binary32 interval collapse. The sampler is binary64 with a `1e-12` endpoint allowance. It does not reproduce every FP32 rounding, intensity clamp or `+1e-5` count tolerance of the Godot shader.

Evidence files deliberately retain all phase metrics and example streams. Rerunning recreates numerical observations within floating-point tolerances; CPU wall times vary. The summary records the Git base plus source hashes because this initial evidence was generated before its implementation commit.

The next step is integration against the actual GPU outputs on identical signals. Spatial moving-edge/shadow behavior, complete GPU event export, renderer-aware adaptation, catch-up/overload behavior, multi-pixel ordering, sustained cost and real-device agreement remain unvalidated. Issue #4 stays open.
